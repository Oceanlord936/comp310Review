//6.10 — Stride scheduling: the deterministic version, worked pass/stride example

Lottery scheduling (6.9) gets the right ratio on average, but with variance in the short run. Stride scheduling gets the exact same proportional-share guarantee,
but deterministically — "the same shares, without the dice."

======================
The mechanism: each process gets two numbers.

1. stride:

stride = (some large constant, call it W) / (process's ticket count).

More tickets → smaller stride. Stride is fixed once tickets are assigned.

2. pass:

Pass = a running total, starting at 0, that accumulates by the process's stride every time it runs. Pass is a kind of "virtual finish line" tracker — it represents how much CPU time (in ticket-weighted units) the process has consumed so far.

=====================

The rule:
at every decision point, run whichever ready process has the lowest pass value.
After it runs one quantum, add its stride to its own pass and repeat.

================
Why this produces the right ratio???

a process with more tickets has a smaller stride,

so its pass grows slower each time it runs — meaning it becomes eligible to run again sooner (lower pass = picked sooner).

A process with fewer tickets has a larger stride, so one turn pushes its pass far ahead, making it wait longer before it's the minimum again.

============
Over time this mechanically forces the run-frequency ratio to match the ticket ratio — no randomness, no averaging-out-over-many-trials needed.

=====================

Worked example: W = 10000. A has 100 tickets (stride 100), B has 50 tickets (stride 200), C has 25 tickets (stride 400). Ticket ratio A:B:C = 4:2:1.

Step Pick (lowest pass) Pass after (A, B, C)
1 A (tie, 0,0,0) 100, 0, 0
2 B (tie, 0 vs 0) 100, 200, 0
3 C (lowest: 0) 100, 200, 400
4 A (lowest: 100) 200, 200, 400
5 A (tie: 200 vs 200) 300, 200, 400
6 B (lowest: 200) 300, 400, 400
7 A (lowest: 300) 400, 400, 400

After 7 runs: A ran at steps 1,4,5,7 → 4 times. B ran at steps 2,6 → 2 times. C ran at step 3 → 1 time. Run ratio = 4:2:1 — exactly matching the ticket ratio, already true after just 7 steps (not just "on average over many trials" like lottery scheduling needed).
