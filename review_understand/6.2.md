The four moments scheduling can happen — tied to the state transitions from 3.3/3.6:

1. running -> waiting
   process vlick itself -> eg request i/o

2. running -> ready
   timer interyypt firts

3. waiting -> ready
   i/0 complete , preemptive

4. running -> terminated
   (process exits) — nonpreemptive

================

A scheduler that only acts at moments 1 and 4 is nonpreemptive (it never interrupts a running process); one that also acts at 2 and 3 is preemptive.

The five criteria (and why they fight each other):

1. CPU utilization
   % of time the CPU is doing something (maximize)

2. Throughput
   — processes completed per unit time (maximize)

3. Turnaround time
   — submission → completion, total (minimize)

4. Waiting time
   — total time spent sitting in the ready queue (minimize)

5.Response time
— submission → first output, not completion (minimize — this is the interactive-feel one)
