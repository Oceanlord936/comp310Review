//4.5: The trampoline trick

The problem.
Switching page tables means writing a new value into satp. That's one instruction. The CPU fetched that instruction through the old table, and it fetches the next one through the new table. So the program counter, which is a virtual address, has to mean something valid in both tables.

The fix. Put the switching code on one physical page and map it at the same virtual address (TRAMPOLINE) in:

1. every process's page table

2. the kernel's page table

Then the PC value stays valid across the satp write. The instruction after it is fetched from the same virtual address, which now resolves through the kernel table to the same physical page. Execution continues without a gap.

---

Why it's at the very top. TRAMPOLINE is the highest page, MAXVA - PGSIZE. A fixed spot that no user program could ever want as heap or stack keeps it out of the way. The trapframe sits just below it for the same reason.

=============

It's used in both directions.

-Entering:
uservec saves registers, loads the kernel satp, jumps to usertrap.

-Leaving:
userret is called from usertrapret with the process's user page table as an argument. It writes that into satp (the same problem in reverse), restores registers from the trapframe, and runs sret.

answer:

The mapping goes one way only. A page table translates a virtual address to a physical address. The hardware never asks "which virtual address points at this physical page?", and it has no table for that direction.

Many virtual addresses can point at one physical page. That's allowed and it's what makes sharing possible. The reverse isn't a problem for the hardware because it never does that lookup.

Is it physically contiguous???

# Yes, in the simplest way. It's one page, 4096 bytes, sitting in one spot in RAM. There's nothing to be contiguous with, because it isn't split up. Contiguity only becomes an interesting question for regions of many pages, like the heap. Those can be scattered across RAM while looking contiguous in virtual memory, and that's the point of paging.
