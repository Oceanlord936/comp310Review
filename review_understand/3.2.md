// 3.2 CPU-bound vs. I/O-bound

process alternate between two kinds of activity , called bursts:

CPU burst: the process is computing.
I/O burst: the process is waiting for a device (disk, network, keyboard).

==================
process types are named by which kind dominates:

1. cpu bound :
   long cpu bursts , few i/o waits
   eg: video encoding , number crunching , spin() in gini

2. I/O bound :
   short cpu bursts , freqeunt waits.
   text editor , web server , file copy

==========================
Why multiprogramming pays off: while one process waits on I/O, the CPU is idle unless the kernel runs another one. With several processes in memory, the CPU runs process B during process A's I/O wait. The CPU stays busy, and that raises utilization.

============================
The catch: it only works because the workloads overlap.

If every process were CPU-bound, there would be no idle gaps to fill, and multiprogramming would just be sharing the CPU. Nothing would speed up.
If every process were I/O-bound, the CPU would sit idle waiting for all of them.
The gain comes from mixing: the I/O-bound processes' waiting time gets filled by the CPU-bound ones' computing.
