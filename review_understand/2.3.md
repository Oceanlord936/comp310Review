// 2.3 System calls as a service interface

A system call is the only "santioned way " for a user program to ask the kernrel to do something privileged :
-touch the files ,create process, allocate memory , use devices .

the kernel expose a fixed menu of services , and program pick from it .

=================================

six family of syscall:

1. process contro :
   fork() , exec() , exit() , wait () , kill()

2. file managememnt :
   open() , close() , read() , write()

3. device management :
   read() / wirte() on devices files
   ioctl()

4. information maintenance
   getpid() , sysinfo (), uptime ()

5. communication
   pipe ()
   sockets , shared memory

6. protection :
   permissions type
   chmod()

=================================
xv6 has 22 syscalls. That is a tiny menu compared to Linux's hundreds, and it is why xv6 is teachable.

Notice:
printf is not write.

write is a syscall: it traps into the kernel and pushes bytes to a file descriptor.

printf is a library function in user space. It formats your string (%d, %s), builds a buffer, and then calls write() (usually through a buffer) to output it.

Library code runs in user mode, and only the write inside it crosses into the kernel.

=========================================
Exam angle: "Which of these is a syscall and which is a library call?"

The test is whether the function itself executes ecall() and enters the kernel.

printf, malloc, strlen and fopen are libraries.

write, fork and sbrk are syscalls.

sbrk(n) : moves the ned of process heap , up by n bytes and return the old break address

and sbrk(-n) can shirnks heap

In xv6, the kernel allocates physical pages and maps them into the process's address space to back the new heap.
