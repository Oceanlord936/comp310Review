//3.3 The process state model

# 5 states model:

1. new :
   being created , not yet ready to run

2. ready :
   able to run , waiting for cpu

3. running :
   currently executing on cpu

4. waiting :
   blocked untile an event happends
   -> I/O finishes , a child exits

5. terminated , being clearn up

=================

Transitions

New → Ready: admitted
Ready → Running: the scheduler picks it (dispatch)
Running → Ready: preempted (its time slice ran out)
Running → Waiting: it asks for I/O or waits on an event
Waiting → Ready: the event it waited for happened
Running → Terminated: it exits

Note that a waiting process goes to Ready, not straight to Running.
It still has to wait its turn for the CPU.

====================

xv6 has six states

1. UNUSED :
   an empty slot in process table , not a process

2. Used :
   new , being set up

3. runnable :
   ready

4. running :
   same as standard running

5. sleep:
   waiting

6. ZOMBIE:
   terminated (exited , but parnet has not collect its pid yet )

   ***

   The extra one is UNUSED, which follows from xv6's fixed table of 64 slots. Each slot is either in use or free, so "free" needs a state. The textbook model has no such state because it doesn't fix the table size
