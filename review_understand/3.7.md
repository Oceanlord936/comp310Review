// 3.7 Context switch mechanics

A context switch is the kernel stopping process A and resuming process B on the CPU.

================================
What happens:

1. save A' cpu state (pc counter , resgister) -> into A's PCS

2. update A' state -> ready if it was preemted , waiting if blocked

3. the shcedluer picks B.

4. Load B's saced state from B' pcb into cpu

5. mark B running and resume it exactoly where it left off

=================================

what is saved :
CPU centext program counter , genral registers
stack pointer , and the state that describes B's address space

--------Key insight: memory is never saved or restored.

A's memory (code, data, heap, stack) stays in RAM the whole time.
Nothing is copied out or back.

That works because each process has its own address space.
B can't touch A's memory, so there is no need to clear anything.

The switch only changes which page table the CPU uses.
It swaps the small CPU context and points the CPU at B's page table.

This is why a switch is cheap,
and why isolation (Part 5.7) makes it possible.

================================

Cost: a context switch is pure overhead,
since no useful work happens while it runs.
Switching too often (a very short time quantum) wastes CPU time,
and that is the quantum trade-off in Part 6.

Link to earlier: this is why the PCB matters (3.4). It holds what gets saved and restored.
