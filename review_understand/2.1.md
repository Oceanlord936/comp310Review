---

is ecall a assembly code in xv6 ??

Yes. ecall is a RISC-V instruction,
so it's part of the hardware's instruction set, not something xv6 defines. Its name is "environment call":
it deliberately triggers a trap into a higher privilege mode

In xv6 it appears in the generated assembly stubs :

(user/usys.S, produced by usys.pl).

li a7, SYS_write # put the syscall number in register a7
ecall # trap into the kernel
ret # return to the caller

---

Your C code calls write(...), which is really that three-line assembly stub. The stub loads the syscall number and executes ecall.

xv6 chose to use ecall as its syscall door.
The instruction itself is standard RISC-V,
and other RISC-V operating systems use it the same way.
