## 10.3 — Address binding: when does a name become a location?

In your source code, things have names: a variable count, a function main.
In memory they need locations, meaning actual addresses.
Binding is the moment a name gets pinned to an address. There are three possible moments:

1. compile time. the location is know before the building , so the compiler and linker write absolute addresses straight into the binary.

example . the xv6 kernel is linked to run at 0x8000000
and QEMU loads it exactly there . The kernel cannot run anywhere else , and moving it would mean recompilling

---

2. Load time. The location isn't known when compiling, so the compiler generates relocatable code.

Every address is written as an offset relative to the start of the program ("start + 340").

When the loader places the program in memory, it adds the real start address to every one of those addresses, once. After that the program is fixed in place, and moving it would mean reloading it.

Correction for your class7.md note: relocatable code has nothing to do with 0x80000000. "Relocatable" just means "addresses relative to my own start," patched by the loader.

---

3. Execution time.

The program may be moved while it runs. That only works if addresses get translated by hardware on every access: the program keeps issuing the same addresses, and the hardware maps them to wherever the program currently is. This is what every modern system does.

The lecture's key line: execution-time binding is what makes swapping, paging and virtual memory possible. The next two lectures depend on it.
