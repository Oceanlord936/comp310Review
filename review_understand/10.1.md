What the CPU can reach directly: registers and main memory, nothing else

- A program must be in directly addressable memory before it can execute. The CPU can't run instructions straight off the disk, so code has to be brought into RAM first. That's why loading (10.5) is a topic at all.

-Only registers and main memory are directly addressable. Registers take about one clock cycle. Memory takes many cycles, and the CPU stalls while it waits.

-Memory is dumb. It only ever sees "address + read" or "address + data + write." Nothing more: no process ID, no permission check, no idea who's asking.

---

That last point is the key to question 2. Memory can't tell which process sent a request, so it can't refuse a bad one

Protection has to happen in hardware before the address reaches memory, and it has to happen on every access. That's the job of the base/limit check in 10.2, and later the page table.
