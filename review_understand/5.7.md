// 5.7 — Isolation via address spaces: why every process switch is also an address-space switch

The core fact from Part 4: every process has its own page table, translating virtual addresses to physical ones.

Virtual address 0x1000 in process A's page table might point to a completely different physical page than the same virtual address 0x1000 in process B's page table. This is what makes isolation possible in the first place — process A literally cannot express a reference to process B's memory, because its page table doesn't contain those mappings at all.

---

What "the CPU is now running process B instead of A" actually requires:

The CPU doesn't consult memory directly — it goes through the currently-active page table (in RISC-V/xv6, the satp register holds the physical address of which page table is active right now — this is from your trap glossary, Part 4). So if the kernel just swapped which process's registers/PC are loaded, but left satp pointing at A's page table, process B would run using A's memory mappings — reading/writing A's data, potentially crashing or (worse) reading things it shouldn't. Isolation would be broken the instant you switched processes without also switching the address space.

===========================

Why this is cheap — and why 3.7's "memory is never saved/restored" made this possible:

Each process's memory already sits in its own set of physical pages, all the time — it never moves, and it's never copied out to some "saved" location during a switch. Switching to a different process doesn't require copying any memory contents at all; it only requires changing which page table the MMU is currently consulting.

That's a single register write (satp) plus a TLB flush — dramatically cheaper than the naive idea of "save all of A's memory somewhere, load all of B's memory back in."

---

One connection worth flagging back to 4.5 (trampoline):

the instruction that actually performs the satp write is itself running in virtual memory — which means it needs to survive having the ground shift under it mid-execution.

So, tying the whole Part 5 arc together: fork() builds a new, isolated address space (5.1); exec() replaces a process's contents but never its identity (5.2); the shell loop and reasoning drills (5.3/5.4) all rely on processes being genuinely separate; exit()/wait() and zombies (5.5/5.6) manage the bookkeeping lifecycle; and 5.7 is the payoff — every one of those transitions is only safe because switching which process runs and switching which address space is active are the same atomic act.
