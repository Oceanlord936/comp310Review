## 10.2 — Base and limit registers: the first protection mechanism

each process gets two hardware registers:

base = the physical address where the process region starts

limit = size of that region

So the process may touch [base, base + limit).

In this scheme, the addresses the program issues are physical. The hardware makes two comparisons on every access:

address >= base AND address < base + limit

If either check fails, the access traps into the OS, and the bad store never reaches memory.

Each process has its own base/limit pair. On every context switch, the OS loads the next process's pair into the registers. Loading them is a privileged instruction.

If user mode could set them, a process could just set base = 0 and limit = all of memory, and the protection would be gone. (This is the dual-mode idea from 1.2 at work.)

That answers question 2 (the stray store): the hardware range check stops the write, before the address reaches memory, on every access. Only the kernel can load those registers.

(GINI-specific) xv6 has no base or limit registers. Its page table does the same job one page at a time (Part 11).

================================
Drill: EXP 6.3 (the first two bullets)

A has base 300040 and limit 120900, so its upper bound is 300040 + 120900 = 420940.

load #305000, rA: is 305000 ≥ 300040? Yes.

Is 305000 < 420940? Yes. Allowed.

---

store rA, #300030:

is 300030 ≥ 300040? No. It fails the lower check, so the hardware traps to the OS. The OS handles it, normally by killing A (in Unix terms, a segmentation fault). Notice the bad address was below A's region, which is why base and limit need two comparisons rather than one.

The last bullet, "on a switch from A to B, what must the OS do?": load B's base and limit. It has to be privileged for the reason above.
