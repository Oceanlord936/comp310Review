//8.1 — The assignment in one slide: Parts A / B / C

T02 asks you to add a new system call, sysinfo, to xv6, built up in three stages:

===========

Part A — add the call.

et a brand-new syscall registered and callable end-to-end:
user program calls sysinfo(),
it travels through the trap machinery, reaches a kernel-side handler, and returns something (even dummy/zero values at first).

The goal here is purely plumbing
— proving the whole path from user space to kernel and back exists and works, before the handler does anything meaningful.
This is where the "five registration sites" (8.6) live — miss one and the call doesn't compile/link/run.

==============

Part B — make it tell the truth.

Now the handler actually computes real data:

how much free memory exists, how many processes are in use, etc.

— by walking real kernel structures
(the free-memory list, the process table) at the moment sysinfo is called, and copying the results back to user space safely

(via copyout, since kernel and user memory are separate address spaces — ties back to 4.4/5.7).

This is a snapshot — one-time computation, done fresh every call.

=============

Part C — make it remember.

The hardest part:
instead of just reporting the current instant, track something over time

— sampling data periodically (via the timer interrupt handler, clockintr)

and maintaining a running history/average

(e.g. average number of runnable processes),

stored in a ring buffer so sysinfo can report a trend,
not just a snapshot.

This introduces a "producer/consumer" relationship: the timer interrupt produces samples in the background, sysinfo consumes them when called.

===================

So the throughline across A→B→C: A proves the pipe exists, B makes it report real point-in-time state, C makes it report state accumulated over time. Each part is strictly harder and builds on the previous one's plumbing.
