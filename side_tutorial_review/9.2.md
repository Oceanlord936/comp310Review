Step 6 is the one that catches people: no stub = no function named sysinfo exists at all.
The stub it generates is 3 instructions: li a7, SYS_sysinfo / ecall / ret

Why "struct sysinfo;" first in user.h:
user.h is included by programs that never include sysinfo.h. Without the forward declaration
they warn about a type appearing from nowhere (and xv6 builds with -Werror).

The handler for Part A:

uint64
sys_sysinfo(void)
{
  uint64 addr;
  argaddr(0, &addr);    // fetch arg 0 (the &info pointer) from trapframe->a0 -- not a C parameter
  return 0;             // lands in trapframe->a0 -> the user sees 0 = success
}

syscall() is the whole mechanism (~15 lines):
num = p->trapframe->a7  ->  p->trapframe->a0 = syscalls[num]()

=====================
The question you will be asked: why is "write" enormous in the histogram?

xv6's user printf sends ONE CHARACTER PER write() call (putc -> write(fd, &c, 1)).
"free bytes:  4096\n" alone is ~18 system calls. Every line sysinfotest prints costs a trap per character.
-> real libc buffers output and makes one write per line/buffer; xv6 does not.
