//8.3 — The whole trip, station by station, as a map

Before diving into code, here's the full round-trip a sysinfo() call makes, as a sequence of named stations. Each one gets its own detailed treatment in 8.4–8.8 — this section is just the map, so you can see how the pieces fit together before zooming in.

=======================================

Station 1 — User call.

Your C program calls sysinfo(&info)
like any normal function call

— from the programmer's perspective, indistinguishable from calling a library function.

=======================================

Station 2 — The stub.
That call actually resolves to a tiny auto-generated assembly function (from usys.pl)

that loads the syscall number into a register and executes ecall. This is the bridge between "looks like a normal call" and "actually triggers a trap."

===================================

Station 3 — Hardware.
The RISC-V CPU executes ecall and does its fixed,
non-negotiable set of actions (detailed in 8.4):

flip to kernel mode, save the current PC, jump to a hardwired trap-handling address.

====================================

Station 4 — The trampoline.
Execution lands in the trampoline page (from 4.5)

— the one page mapped at the identical address in every page table, which exists specifically so the CPU has somewhere valid to execute immediately after switching page tables (since switching page tables mid-instruction would otherwise strand execution). It saves the rest of user state into the trapframe (from 4.4) and switches to the kernel's page table.

====================================

Station 5 — usertrap.
Now fully in the kernel with the kernel's page table active,

usertrap() runs
— the single C function that handles every kind of trap from user mode (syscalls, interrupts, exceptions alike, per 2.1's "one mechanism, three causes").

It inspects scause to figure out this was a syscall, and dispatches accordingly.

===================================

Station 6 — syscall().
usertrap calls syscall(), which reads the syscall number
placed in a register by the stub back in Station 2

and looks it up in a table of function pointers

— this is the "call-by-number instead of call-by-name" mechanism from 2.4.

=====================================

Station 7 — Your handler. The table entry points to your actual sys_sysinfo() implementation — the C function you write, which fetches arguments (8.7) and does the real work (Parts A/B/C from 8.1).

=====================================

Station 8 — Back home.

Your handler returns a value, which gets placed back into the trapframe, and the reverse trip happens: back through the trampoline, sret restores user mode and the saved PC, and your user program resumes right after the ecall as if it were a normal return (8.8).

========

This map is the skeleton for everything in the rest of Part 8 — 8.4/8.5 zoom into stations 2–6, 8.6 covers the registration sites that make stations 6–7 connect, 8.7 covers station 7's argument-fetching, 8.8 covers station 8.
