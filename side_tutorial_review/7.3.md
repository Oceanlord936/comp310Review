//7.3 — alloc: lazy/demand paging made visible

alloc is a GINI Memory-face tool built to make lazy (demand) allocation observable — the idea that a page can be reserved (address space grows) without actually being backed by physical memory until the process first touches it.

---

The mechanism it needs is "sbrklazy "

a GINI-specific variant of sbrk that grows the process's address space lazily: it extends the valid virtual address range immediately, but doesn't allocate/map physical pages behind it yet. Those pages stay unmapped until the process actually reads or writes into that region,

at which point a page fault occurs (this ties back to 2.6 — exceptions/page faults aren't all errors) and the kernel handles it by then allocating a physical page and mapping it in, on demand.

============

alloc exists specifically to make that two-step process visible: call sbrklazy to grow the address space (nothing allocated yet — you can watch the Virtual Memory face show a valid-but-unmapped region), then actually touch that memory (write to it),
and watch the kernel field the resulting page fault and allocate a real physical page right then. It's a live demonstration of the lazy-allocation exception path from 2.6, using GINI's own memory face rather than just reading about it.
