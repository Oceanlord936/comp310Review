//9.1 — Orientation gut-check (before touching kernel source)

Sources: T01-GINI-xv6-Orientation.pdf (slides 5-9, 14), ALab01_Sysinfo_Student.pdf (Part 0)

=====================
Getting in:

gBuilder -> press Run -> double-click the xv6 machine -> Machine Lab opens -> click "User Code"

User Code = home face for the lab:
- lists your 10 files, shows which ones you changed
- ticks off each step as you complete it
- checks all six registration sites against your source BEFORE the build runs

Buttons:
Load      compiles your kernel and restarts the machine with it (~1 second)
Revert    throws away your changes to ONE file, puts the original back
Keyboard  type at the xv6 shell

Your files live on your laptop, not inside the machine:
~/.gini/xv6-lab/<machine-name>/
(syscall.h syscall.c sysproc.c defs.h kalloc.c trap.c sysinfo.h user.h usys.pl sysinfotest.c)
GINI links them into the kernel source inside the machine -> what you write is what gets compiled.

=====================
Faces to check your work against:

User Code         the step checklist
System Calls      histogram = every kernel crossing, live. trace below = one line per call
Process Scheduler compare against your nrunnable
Virtual Memory    compare against your freemem (free-page count)

How panels update:
the agent polls ~once per second over the serial line -> the kernel is NEVER paused for this
exception: "Step a trap" uses gdb and really halts the CPU for a moment

blank / frozen panel = no frame came back -> kernel wedged or busy, or the image is older than the panel

=====================
THE RULE THAT BITES: what survives what

Action          What restarts        Your kernel edits?
REBOOT          QEMU only            kept on disk, but NOT compiled in -> old kernel still runs
REBUILD (Load)  make, then QEMU      compiled in
STOP + RUN      whole container      kernel files survive (on laptop); files made INSIDE xv6 are gone (fs.img lives in the container)
QUIT gBuilder   everything           projects, shadows, proofs all still on your disk

---

#1 mistake: "I edited the kernel and nothing changed"

cause 1: rebooted instead of rebuilding. Nothing is read at run time -- it all gets compiled in.
cause 2: the build FAILED. A kernel that does not compile leaves the machine running the one it had.
-> always check the build output when a change seems to do nothing.

Safety net: every file has Revert, and a broken build keeps the old kernel -> you cannot get stuck.
